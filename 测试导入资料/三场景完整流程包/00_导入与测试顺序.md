# 三场景完整流程包：导入与测试顺序

生成日期：2026-11-07。用途：在知行研学平台实际测试三个学生场景、年度试卷和教师教学闭环。所有内容为原创模拟资料，包含同工作区既有原创讲义的整理扩写；不是官方考纲、正式真题或学科覆盖承诺。所有案例人物、地点、机构、数字和事件均为虚构。

## 一、准备与文件分工

打开 http://127.0.0.1:5183 。若本机服务未启动，在项目目录运行已有发布启动脚本；本资料包不会自动启动、配置或更改平台。请使用三个独立学习项目，避免场景数据混杂。教师与学生使用不同浏览器配置文件，以免登录会话互相替换。

个人自主学习可在登录页注册新账号。教师链路需要平台现有且同班级关联的教师和学生账号；个人注册不会自动加入班级。发布环境不会自动创建文档中的旧演示账号。

## 二、先区分哪些操作需要模型

| 操作 | 依赖 |
|---|---|
| 创建项目、保存笔记、导入JSON、生成测评快照、客观题规则判分 | 不需要生成模型 |
| 读取普通文本、平台侧全文搜索和原文定位 | 不需要生成模型 |
| 助教知识库索引 | 需要配置好的DeepTutor及嵌入服务；可能异步排队 |
| 答疑、精读、讲题、学习引导、生成新题与独立模型校验 | 需要真实模型，会发生模型调用 |
| 分析题训练反馈、教师AI初评、错题AI诊断和针对性练习 | 需要真实模型 |
| 到时交卷、证据同步及后续复习 | 需要对应后台进程；原生复习还依赖DeepTutor，复习出题可能调用模型 |

纸卷题目已随JSON提供，不必先运行AI出题才能开始。但分析题反馈仍需要模型；原生索引可能随资料导入自动安排，不能据此宣称导入过程绝无外部依赖或费用。失败应显示原因，不能拿模拟成功结果替代真实执行。

## 三、场景一：首次学习新课程

1. 新建项目，场景选“首次学习新课程”，名称“测试A｜实践与认识新课”，每日30分钟。此场景不要求目标分和考试年份。
2. 检查优先引导到添加本章资料，上传01。等待正文可读，若助教索引未就绪，使用“准备或重试索引”，最终应显示就绪或明确失败原因。
3. 进入阅读任务，写下自己的理解，保存学习位置，刷新后检查恢复。
4. 点击“读讲义”，再追问“间接经验为什么不否定认识来源于实践？”；也可使用随学助教。核对引用能打开对应原文，返回项目后查看答疑记录。
5. 点击“完成阅读，检查理解”，在后续理解检查任务准备单选题。提交前应看不到正确答案。
6. 为覆盖错误路径，可以作答后检查是否答错；若碰巧答对，不修改旧记录，在下一次可用练习中继续覆盖错误分支。答错后检查反馈和补学任务。
7. 完成补学，使用新题独立验证。另用一个任务先请求提示，检查辅助记录不被当成独立通过。
8. 在“笔记与闪卡”各保存一条记录，刷新，展开闪卡背面。查看证据报告，阅读和独立通过应分开。

本场景不要求固定出题数量或固定选项。学习路径如返回有依据的建议，需主动“加入学习计划”；查看建议本身不能直接产生独立掌握证据。

## 四、场景二：期末复习

1. 新建“测试B｜辩证方法期末复习”，场景选“期末复习”，每日45分钟，考试日期可设为2027-01-15。
2. 上传02，检查引导为添加考试范围资料。第一次进入尚无题库时，应提示先学习并准备题目，而不是直接提供空测评。
3. 阅读复习资料与综合案例，通过学习任务准备题目。按实际任务继续，积累至少2道可用题；也可以先用1题验证组卷入口，不要求系统凭空生成额外任务。
4. 回到项目，检查“开始成组练习”入口；进入后应带入本项目，模式为成组练习。若尚无题，继续理解检查，不把空题库当作导入失败。
5. 命名“辩证方法阶段自测”，选题并开始，等待草稿保存后刷新恢复。设置一道错误作答，整组交卷后检查补学。
6. 对照概念比较表，检查讲题和反馈是否区分主要矛盾与矛盾主要方面，不能只看结论而忽略分析层次。
7. 暂缓一个未完成任务，再从项目恢复。调整每日时间，检查计划版本更新，报告只覆盖已发生的证据。

本场景仍使用考研政治出题与分析题规则，不代表任意学校课程的期末评分体系。不要将本包命名为统计学等学科。

## 五、场景三：考研备考

1. 新建“测试C｜2027政治备考”，选“考研备考”，年份必须为2027，每日60分钟，目标分可填70。
2. 在课程与资料上传03；在年度考纲与试卷依次导入04、05、06，每次只选择一个JSON并点击导入。新项目优先打开年度页，不妨碍切到资料页上传讲义。
3. 检查考纲为六模块十二主题，主题名称与讲义代码相对应。12个主题只是示例，不是全科覆盖。从考纲点击“学习这个知识点”，开始对应任务。
4. 搜索“统计口径”“主要矛盾”等词，打开核对原文；本包Markdown以提取文本和行位置核对，不应出现伪造PDF页码。
5. 对05先选“按原卷练习”，检查12题、顺序、题型与分值；完成后核对客观题分数，分析题反馈单列。
6. 如要测试限时模考，再由原卷入口新开一场。一个项目不要同时启动多个模考；交卷前助教、学习原文与学习会话读取受限。确认已交卷后再进行下一场。
7. 查看补学和报告。考纲已学习与已独立验证应有区别；70分是目标，不应显示为模型已证明的全科预测分。

文件05为48分模拟短综合卷，不能当作100分正式考研卷。文件04在页面中即使显示“年度考纲”标签，标题和来源仍应表明“模拟、非官方”。

## 六、五分钟短卷：自动保存与服务器到时交卷

在完成其他模考后，对06点击“限时模考”，确认开始后计时5分钟。第1题选A，第2题选B、C，分析题写一段自己的解释；等待界面明确显示“草稿已自动保存”。

先刷新一次，核对答案恢复，再关闭该浏览器标签页。等待超过截止时间后重新打开平台，进入该测评。后台期限维护进程正常时，应已结束或读取到到期处理结果，客观题为6 / 6，分析题训练反馈可能仍在排队。到时只用服务器最后成功保存的内容，不使用关闭前尚未保存的输入。

若要测试漏选分支，另开一场，仅第2题选B，其余同上，客观题应为2 / 6。不要修改已交卷答案。双标签同时编辑的冲突测试放在另一场测评，冲突时系统不能静默覆盖；这与正常草稿恢复分开记录。

短卷服务端到期处理与模型反馈是不同环节。客观题已判、分析题待评价，不等于没有交卷。若迟迟未到期处理，记录测评ID、截止时间及后台进程状态，不要反复新开同一场来掩盖问题。

## 七、教师—学生教学闭环

1. 教师账号进入“教学内容 → 导入新资料”，上传07，保留原创测试授权说明；不要上传08。等待原文解析就绪。
2. 设置1道单选、1道多选、1道分析题，点“启用并生成”。根据当前原生路径等待索引、出题与校验，不在处理期间重复点击。失败时记录错误，使用恢复或重试入口。
3. 核对实际题目、四级提示、原文引用和分析题评分要点。未经核验的候选题不应进入可用题库。可以编辑或停用需要处理的题目。
4. 在“作业与批阅”勾选本批题目，命名“调查研究与矛盾分析测试作业”，选择学生所在班级，一次发布。检查作业读取发布时的题目和来源版本。
5. 学生从“教师作业”逐题填写答案与思考过程，测试保存和刷新，再提交整组。单选故意选错、多选故意漏选；若为盲测，可以由测试者在交卷后确认是否覆盖到错误分支。
6. 检查客观题系统判分，分析题显示AI初评待教师确认。教师查看作答并确认或修改评分；学生再查看正式分。分析题AI建议不能提前写成正式成绩。
7. 学生提出评价异议，教师在“评价复核”处理并说明理由，检查评价修订历史仍在。
8. 学生“错题诊断”核对原题、选项、选择、思考过程和来源，主动点“AI诊断”，完成后再点“生成针对性练习”。新题答完后查看证据和后续复习。个人练习不应混入班级公共题库。
9. 学生从作答中的学习助手发起“转教师帮助”，教师在“学习困难转办”回复。教师选已有知识点测试AI备课，编辑并保存草稿，不应自动发布。

教师在原作答“补学、验证与AI证据”回看整条链路。07讲义能够支持题目生成，但模型每次题目不固定，不能套用08中两份JSON试卷的答案。

## 八、共用功能、权限与测试收尾

- 在一个项目切换场景，检查资料和作答保留，引导发生变化。场景选择在本浏览器保存，不以跨浏览器同步为验收条件；三个场景仍应各自完成一次主流程。
- 使用另一学生账号检查项目、原文、答疑和作答隔离。正常页面无权访问即可记录，不需猜测数据库或遍历他人资源。
- 模型任务失败时，检查错误、草稿及原件保留，失败不得伪装成演示结果。中止和恢复后不要把重复题目当作新进展。
- 复习以实际启用的队列为准。若显示Mastery Path，按其到期与掌握门槛检查；不要求首次答对后立即出现到期任务，也不固定套用旧版1、3、7天。
- 管理员可测试AI真实连接与创建机构账号；这些步骤需要对应账号权限，真实连接会调用模型。
- 移除资料、撤回来源和归档项目放在最后，只对本包测试记录操作；检查权限变化、今日安排与历史保留。

记录问题时填写：场景、账号角色、项目或作业名称、题目或运行ID、操作步骤、预期、实际结果、北京时间与截图。不得将模型密钥或私有运行配置放入问题记录。

## 九、静态交付验证与实际运行的区别

本包交付时使用平台现有ResourceInput、Topic和PaperQuestion校验JSON，并检查题号、分值、答案、讲义引用、主题映射及文件限制。静态验证不启动平台、不写数据库、不调用模型，不等于已完成页面导入、实际生成或教师人工审核。

每个JSON的年度、类型、版本组合唯一。重复导入同一版本被拒绝属于预期；需要重新测试可使用新项目，不要为了重导覆盖历史数据。若改项目年份，考纲也必须同步调整，建议本轮保持2027以减少变量。
