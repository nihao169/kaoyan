# ADR 0001 模块化单体与首版基础设施

日期：2026-10-27　状态：采用

## 背景

项目从技术路线开始，需要长期支持多科目、多机构；当前首先验证小规模考研政治的学习、评价和内容闭环。过早引入分布式基础设施会增加开发与恢复成本。

## 决策

采用 React 前端、FastAPI 模块化单体、独立 worker，关系模型由 SQLAlchemy 与 Alembic 管理。SQLite 限定本地和受控演示，持续多人使用前迁移 PostgreSQL。存储和评分提供必要适配接口，AI 经统一网关与 LangGraph 编排。

身份采用全局用户加机构成员关系。科目动态关联。原始作答、正式评价、AI 建议和发布版本独立保存。发布与评分使用幂等及审计。外部模型调用不占用业务写事务。

## 代价

首版 API 与 worker 共享数据库，SQLite 写并发有限。模型调用可能重复计费，但正式业务结果去重。检查点数据库与业务数据库备份必须在停止写入后协调完成。小规模聚合接口需在扩大试用前补充分页。

## 不采用的方案

不以微服务、向量库或消息中间件作为开工前提；不使用模型自由文本修改业务状态；不把所有知识和学习记录混入向量库；不以启动自动建表替代数据库迁移。

## 重新评估条件

出现稳定写锁竞争、持续队列积压、明显独立扩缩容需求，或团队拥有独立模块发布责任时，依据 architecture.md 的演进条件调整，并增加新的 ADR。
