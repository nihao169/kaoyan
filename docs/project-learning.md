# 项目学习流程

首次学习（chapter）、期末复习（final）、考研学习（kaoyan）都保存到服务端。场景、课程、目标、时间预算、考试年份只作为 DeepTutor 的学习背景，不对应平台预先排好的教学步骤。

学生从项目的“与助教学习”进入。助教使用原生 Mastery Path 完成需求沟通、大纲讨论与确认、教学、理解检查、掌握证据和复习安排。页面展示原生知识点地图、待回答问题和会话；关闭页面后可以继续。今天学习、学习报告读取同一学习路径。

## 资料和功能联动

- 没有资料时可以沟通目标、基础与学习范围；正式教学要求项目有权访问的全部资料索引就绪。支持教师已启用课程资料、个人上传、粘贴文本和现有年度资料导入。平台不自动获得教材版权或内置所有课程教材。
- 精读使用原生 Immersive Reading，会话按资料分别保存；可从“返回引导学习”回到项目路径。
- 选定笔记作为原生 Notebook 引用交给助教讨论大纲，先展示建议、确认后修改。原笔记和闪卡保留。
- 集中练习读取当前路径已保存的 Question Notebook 题目，使用原生 Practice 的版本检查、幂等提交与练习记录。主观题需显式自评。Practice 的自评不直接写成 Mastery Path 掌握证据。
- 政治课程保留既有政治专项测评、年度模拟资料。通用课程不展示政治出版社书目，不允许添加政治模拟资料。Full Book 生成界面不在本次接入范围。

## 历史、权限与恢复

旧项目第一次进入需要确认场景、课程与目标。历史任务、笔记、成绩、证据保留；确认后的项目不再由旧任务引擎安排日程与补学。历史学习任务只读，测评继续保留。旧版客户端未确认的项目暂保留兼容接口，主界面统一走确认入口。

每个项目按资料范围绑定原生路径。调整目标或时间预算保留同一路径和有效证据；资料范围变化建立新绑定，旧绑定保留，不把撤回资料的学习现场带入新范围。归档后只读。每次读写检查用户、资料权限和独立模考限制。

学习请求先持久化到平台队列，再由工作线程在数据库事务外调用原生接口。失败恢复复用同一提交标识；原生题卡和暂停澄清分别使用对应回答协议。原生会话执行失败时显示错误，保留已有会话和证据。HTTP 超时不视作教学成功。

## 运行与验证

数据库迁移：`a418f6d28c09`，增加课程、目标、背景确认字段和 `v2_project_learning` 绑定表。正式切换前使用 `scripts/backup-v2.ps1 -Release` 做一致性备份，随后重启桥接容器并执行 `scripts/start-release-v2.ps1`，该脚本先迁移再启动服务。

自动检查：后端 `test_project_learning.py`、`test_v2.py`、`test_v2_native_storage.py`、`test_mastery_reviews.py`、`test_v2_migration.py`；前端 `npm run test:e2e:v2`、`npm run test:api` 和 `npm run build`。浏览器契约测试与真实模型验证分开执行。

隔离真实服务验证：先准备 `tutor-native-preview-*` 容器及其模型/嵌入配置，再运行 `scripts/verify-project-learning.py <preview目录>`。附加 `--teaching` 验证大纲保存、教学、理解检查及回答。该脚本仅接受工作区 `.runtime` 下的预览目录，使用独立原生身份，不使用正式项目。
